### PI Agent · 2026-10-11 15:55:44

递归就是**函数自己调用自己**，把大问题拆成结构相同的子问题，直到碰到终止条件再逐层返回结果。

### 自动化里最实用的 3 个场景

1. **遍历未知深度的文件夹**  
   文件夹里还有文件夹，层数不固定，循环写起来很丑，递归最干净。
2. **解析嵌套 JSON / YAML**  
   配置自动化时经常遇到嵌套结构，递归能无痛穿透任意层级。
3. **任务拆分与重试**  
   比如批量处理 API 分页，或把一个大任务拆成子任务直到原子级别。

### 极简代码（Python）

```python
import os

def find_files(root, target):
    """在 root 目录下递归查找 target 文件"""
    result = []
    for entry in os.scandir(root):
        if entry.is_dir():
            result += find_files(entry.path, target)  # 自己调用自己
        elif entry.name == target:
            result.append(entry.path)
    return result

# 用
# files = find_files("/Users/azhe/Projects", "config.yml")
```

### 递归的三要素（缺一不可）

1. **终止条件**：什么时候停？（上面代码里 `is_dir()` 为 False 时不再深入）
2. **自我调用**：怎么把问题变小？（对子目录再执行 `find_files`）
3. **收敛性**：每次调用都更接近终止条件（路径往下走，目录有限）。

### 什么时候别用递归

| 情况 | 建议 |
|------|------|
| 层级可能很深（>1000） | 用循环 + 栈，Python 默认递归深度限制 1000，会爆栈。 |
| 性能敏感且子问题大量重叠 | 用循环或加 `functools.lru_cache`，否则重复计算拖慢速度。 |
| 逻辑本身线性、层级固定 | 直接 `for` 循环，别炫技。 |

### 一句话总结

**层级不确定、结构自相似 → 递归；层级确定、追求极致性能 → 循环。**

那很妙——火箭的本质可以用一句“反作用 + 动量守恒”概括：它自带推进剂，把燃气高速向后喷出，靠反冲获得向前的推力，所以真空中反而更“干净”。

关键线索一般是这几条：

- 推力：近似 \(T=\dot m v_e\)，更完整要加上喷管出口压力项 \((p_e-p_0)A_e\)。
- 比冲：\(I_{sp}=v_e/g_0\)，像“每单位推进剂能换来的冲动”，越高越省燃料。
- 火箭方程：\(\Delta v = v_e \ln(m_0/m_f)=I_{sp}g_0\ln(m_0/m_f)\)。这里能看明白为什么火箭大头是燃料、为什么需要多级。
